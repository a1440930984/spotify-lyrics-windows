# SpotifyLyricsWin v0.7 使用说明

Windows 上播放 Spotify 时显示桌面悬浮歌词的小插件，外观与逐字算法按安卓版
SpotifyLyrics V2.4 复刻（见同目录《外观复刻规格.md》）。

v0.7 的改动：默认主题改浅色、深蓝与纯黑拉开差距、悬浮背景与主题解耦、
广告连播段识别、机器翻译兜底（无译文时自动翻中文）、繁体转简体开关、
译文比例字号 + 译文扫光、字号范围放宽到 12~60、锁钮改悬停显隐 + 位置恒定、
字体列表剔符号字体 + 滚轮不卡页面、预设色块扁平化、图标透明底放大。
详细逐条见 CHANGELOG。

## 怎么运行

1. 解压 `SpotifyLyricsWin-v0.6.zip` 到任意文件夹。
2. 双击 `SpotifyLyricsWin.exe`（已在运行时重复双击不会开第二个，新进程会直接退出）。
3. 打开 Spotify 桌面版放歌，悬浮歌词会自动跟上。
4. 自动更新开箱可用（仓库已公开，不用填任何令牌），见下一节。

## 自动更新（v0.4 新增，v0.6 免令牌）

- 程序启动后会静默检查一次；有新版只弹一个托盘气泡（不弹窗、不打断听歌），
  点气泡或进设置就能看到新版说明
- 设置窗「自动更新」分区里点**「检查更新」**可随时手动查（已是最新也会明确告诉你）
- 点**「立即更新」**：自动下载新版 zip（带进度百分比）→ 程序退出 → 独立小助手
  （SpotifyLyricsUpdater.exe）在后台换好文件 → 自动重新打开，并汇报「已更新到 vX」
- 更新包从 GitHub Releases 拉取，发版是全自动流水线（打 tag 即云端构建发版）

### 令牌（可选，仓库切回私有时才需要）

仓库已转**公开**，不填令牌也能检查/下载更新（匿名）。设置里的令牌框**保留**：
以后仓库若切回私有，填一枚只读令牌即可继续用（填了优先用令牌）。令牌**只填在
App 设置里、只存你本机**（`%AppData%\SpotifyLyricsWin\settings.json`），
**不要发到任何聊天里**：

1. GitHub 点头像 → **Settings** → 左下 **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. 名字随便起（如 `spotify-lyrics-update`）；有效期尽量选长
3. **Repository access** 选 **Only select repositories**，只勾
   `spotify-lyrics-windows` 这一个仓库
4. **Permissions** 里只给 **Contents: Read-only** 一项，其余不用动
5. 生成后把令牌复制到 App 设置窗「自动更新」分区的输入框（有「显示」按钮可核对），
   改动即自动保存

### 更新失败了去哪看

- 下次启动时设置窗的状态行会直接报上次更新的结果（成功到哪版 / 失败原因）
- 细节日志：`%TEMP%\SpotifyLyricsWin-update\updater.log`（小助手每步都写了人话）
- 结果文件：`%AppData%\SpotifyLyricsWin\update-result.json`
- 若小助手没能自动启动，设置里会把它的完整路径和参数留在状态行，
  手动运行那一行也能完成更新

**运行前提**：需要 .NET 8 桌面运行时（框架依赖版）。如果双击没反应或弹缺运行时，
去微软官网装「.NET 8 Desktop Runtime (x64)」再试。程序不需要管理员权限、不改 Spotify 本体。

## 托盘操作

程序在系统托盘（绿色歌词图标）里：

- **双击图标**：打开设置
- **右键菜单**：显示/隐藏歌词、设置…、手动选词…、重新搜词、**这不是广告**
  （仅广告提示时可点）、**标记为纯音乐 / 取消纯音乐标记**、打开日志、退出
- 图标悬停提示会显示当前歌词来源（如「歌词：酷狗 KRC｜晴天」）

## 悬浮窗操作

- **拖动**歌词：移动超过一点距离才算拖动，松手自动记住位置
- **轻点 / 鼠标悬停**歌词：窗口上方扩出一小条按钮带（🔓/🔒 锁定、✕ 隐藏），3 秒后收回。
  按钮带是窗口向上新扩的区域，**歌词位置纹丝不动、永远不会被按钮盖住**；
  v0.5 起按钮带是深色半透明胶囊，图标加大且带深色阴影，白底黑底都看得清；
  v0.6 起按钮带**居中固定**（窗口宽度取歌词行与按钮带的较大者，长短句共用同一中轴，
  切歌词时锁钮不再左右移位）、按钮改纯自绘幽灵样式（没有选中底色/焦点框，悬停只有
  轻微高亮，锁定态是绿色图标本身）、显隐带约 180ms 淡入淡出动画
- **锁定位置**：点 🔓 变 🔒 后整窗拖不动（按钮本身还能点）；设置里和右击菜单里也能切换，三处状态一致
- **右击歌词**：弹出菜单（深色）——打开设置、手动选词、重新搜词、这不是广告、
  标记为纯音乐/取消标记、锁定/解锁位置、隐藏歌词
- **双击**歌词：打开设置
- 暂停时歌词整块变淡（38%），恢复播放自动变回；关掉 Spotify 后显示「♪ 等待 Spotify 播放」

## 窗口外观（v0.6 Fluent 外壳 + 多主题）

v0.6 起设置窗与手动选词窗换成 **WPF-UI（Fluent 界面库）的 FluentWindow**：
Mica 质感、库标题栏、库原生控件（卡片/开关/数字框/输入框），观感向 Win11 系统
设置靠拢。颜色盘保留自绘（配色跟随主题）；悬浮窗与托盘菜单不变。

**界面主题**（设置第一张卡）：4 套预设——**浅色**（默认）/ **Spotify 深色** / **纯黑（OLED）**
/ **深蓝**。其中纯黑与深蓝两套会关掉 Mica 材质让主题色真正生效（v0.7）。切换后设置窗会自动关掉重开换装（位置回到原位，滚动位置
会重置）；主题只换窗口界面配色，**悬浮歌词的文字颜色仍由「颜色」设置决定**，
两套互不干扰。强调色：深色三套是 Spotify 绿，浅色套用稍深的绿保证白底上看得清。

**窗口位置记忆**：设置窗、手动选词窗第一次打开在主屏幕居中，之后记住上次的位置、
下次原位打开（关窗时保存）。颜色盘不记忆，每次居中于设置窗。

窗口标题规则：设置窗带程序名与版本号（「Spotify 歌词 · 设置 v0.7」），
子窗口只写功能名（「选择颜色」「手动选词」）。

## 设置说明（改动实时生效，没有保存按钮、也没有「完成」按钮）

设置窗里任何改动都**立刻应用到悬浮窗**并自动存盘；关窗请用标题栏 ✕
（v0.3 起删掉了底部的「完成」——实时生效下它没有实际作用）。

- **界面主题**：4 套预设，见上方「窗口外观」一节
- **平滑逐字高亮**：卡拉OK 式渐变扫光；关掉则整行变色
- **显示译文**：歌词源带译文时在当前行下方显示一行译文（字号比原文小 6、透明度 0.78）。
  v0.6 起：中文歌不再显示译文（源给的多半是原文重复）；主源没译文时后台自动
  向网易云补一份译文，补到后无缝替换并存缓存
- **锁定悬浮窗位置**：与悬浮窗上的 🔒 按钮等效
- **显示行数**：双行（当前行 + 下一行，默认）/ 单行（仅当前行；译文行仍按上面的开关）。
  单行模式下当前行在窗口内**水平、垂直双向居中**；切换行数时窗口围绕中心重新量尺寸，不跳位
- **歌词字号**：12~36（数字框），长句会自动逐级缩小（最低 11）不截断
- **高亮/文字颜色**：三种改法实时生效——填十六进制（#AARRGGBB）、点色块或「颜色盘…」
  打开颜色盘、点 12 个预设色
- **背景框透明度**：0 = 纯文字无框（默认推荐）；调高出现黑色圆角底框
- **歌词时间偏移**：歌词整体快/慢时用 ±0.1s 按钮微调，范围 ±30 秒
- **字体**：默认 Microsoft YaHei UI 粗体，可换系统里任意字体。列表**显示中文名**
  （如微软雅黑/幼圆），每项以自身字体渲染预览；未展开时鼠标滚轮不会误改字体
- **Musixmatch API Key**：可选，见下方已知限制
- **自动更新**：令牌（可选，遮罩 + 显示切换）、检查更新、立即更新，见上方专节
- **纯音乐标记**：设置里可看全部标记名单并一键清空（标记怎么来的见下方专节）
- **诊断日志**：设置窗内有日志路径和「打开日志」按钮，见下方广告一节
- **恢复默认外观**：字号 18、绿高亮、白字、无背景框、逐字开（点击即实时恢复）

### 颜色盘的新交互（v0.3）

- 点色块或「颜色盘…」打开，窗口**居中于设置窗**弹出，标题栏只有关闭键
- **没有确认/取消按钮**：拖色板、拉色相条、点预设、改 hex，选色**实时**就应用到
  悬浮歌词上；关掉窗口即保留当前颜色
- **点到窗口外（别的程序/桌面）会自动关闭**，颜色已实时生效，不会丢；
  在窗内点 hex 输入框等操作不会误关

设置保存在 `%AppData%\SpotifyLyricsWin\settings.json`，歌词缓存（增强 LRC 文本）在
`%AppData%\SpotifyLyricsWin\cache\`，同一首歌第二次播放直接读缓存。
**注意**：v0.3 起曲目 key 改用简体（繁体标题会转简体再做 key），v0.2 的旧缓存会
失效一次，第一遍播放重新取词，之后照常走缓存。

## 手动选词

自动搜的歌词不对版时用：托盘菜单或右击歌词 →「手动选词…」。

1. 窗口打开时已预填当前曲目的歌名/歌手（v0.3 起预填自动转成**简体**显示；
   繁体标题如「愛的供養」会显示为「爱的供养」；可改，比如去掉歌名里的 Live/Remaster 后缀）
2. 点「搜索」：并行查酷狗 / QQ / 网易云 / 酷我 / LRCLIB，候选以卡片列出
   （歌名、歌手、时长、来源徽章、逐字/逐行徽章）；某个源失败会在底部单独标明原因，不影响其他源
3. 选中一张卡（或双击）→「应用选中歌词」：立即换上，并记为当前曲目的歌词（覆盖缓存，
   下次播这首歌直接就是这版），卡片上出现「✓ 已应用」
4. 酷狗候选里可能混着半截歌词（DJ 版/片段版），认准时长接近整首的再应用
5. 窗口底部有「把当前曲目标记为纯音乐」：这首歌是纯音乐/伴奏时点它，以后不再白搜

## 纯音乐标记（v0.6 新增）

没有歌词的曲子不再反复白搜、也不再误报「未找到歌词」：

- **自动标记**：歌曲标题带「纯音乐 / 伴奏 / Instrumental / (inst)」等特征词时，
  自动判定为纯音乐，不取词，悬浮窗显示「♪ 纯音乐 · 无歌词」
- **手动标记**：悬浮窗右击菜单、托盘菜单选「标记为纯音乐」，或手动选词窗里的按钮；
  取消同样在这三处（菜单文案会变成「取消纯音乐标记」）
- 标记按「歌名|歌手」存进设置（上限 500 条），设置窗「纯音乐标记」卡片里能看到
  全部名单并一键清空

## 广告识别（启发式）与诊断日志

免费版 Spotify 放广告时，悬浮窗会变淡并显示「广告播放中 · 歌词马上回来」，
广告结束自动恢复歌词同步。

- 判定规则（照 SMTC 给的曲目信息特征，宁漏勿误杀）：①标题含 Advertisement；
  ②歌手/标题含**域名样式**（如 HepatitisBTesting.com 这类把网址当歌手名的广告主，
  不受专辑保护）；③**关键词加权**（v0.6 并入两家安卓实现的词表：广告/赞助/推广/
  sponsored/spotify premium/music will resume 等，命中 +2 分、时长 ≤45 秒再 +1 分，
  满 3 分才判——单独一个词不判，防真实作品名带词误杀）；④**专辑为空且时长 ≤35 秒**
  （不看封面——真实广告 T-Mobile 10s / Instacart 30s / McDonald's 15s / Lowe's 30s
  全都有封面，v0.3 规则要求「无封面」正是它们全部漏检的原因）；
  ⑤歌手与专辑都为空且时长 ≤90 秒。保护线：有专辑名的除②③外永不判；
  时长 >90 秒除①外永不判
- **判错了怎么办（v0.6）**：广告提示显示时，在悬浮窗右击菜单或托盘菜单点
  **「这不是广告」**——立刻恢复取词，并且这首歌会被记入抑制名单（存设置、上限 200），
  以后同曲永不再判广告
- **局限**：这是启发式，个别把自己伪装成正常歌曲（有歌手、有专辑、时长像歌）的广告
  识别不了，会当成一首搜不到词的歌处理；反过来，专辑信息缺失的超短真实片段
  （≤35 秒、专辑为空）可能被④误判——现在可以一键「这不是广告」纠偏，
  也可以把日志发回来调规则。v0.6 起 SMTC 日志行会附带「可切歌/可快退/可拖动」
  等动作信息（只记录、不参与判定），为下一轮规则调校攒数据
- **诊断日志**（v0.3 起全量记录）：程序每次切歌/状态变化都会往
  `%AppData%\SpotifyLyricsWin\log.txt` 记一行（时间、标题、歌手、专辑、时长、
  有无封面、播放状态、本次判定），程序启动也记一行，所以**这个文件必然存在**，
  不再像 v0.2 那样没命中过广告就找不到文件。日志上限约 200KB，超了自动截断保留后半。
  打开方式：托盘菜单「打开日志」，或设置窗里的「打开日志」按钮
- **广告没识别出来时怎么办**：开着日志，等广告播完（或截下广告时段前后的几行），
  把那几行日志发回来，就能看清广告时段 SMTC 实际上报了什么，针对性回调规则

## 逐字进度为什么不跳了（v0.5 平滑时钟）

旧版跟踪进度的方式有个毛病：每 500ms 问一次系统进度，差不到 1.5 秒就当没看见
（死区），攒够了再一下跳过去——逐字扫光于是「跑快了又回退，跟唱对不上」。
v0.5 换成安卓版同款的 observe 思路：每个进度样本都交给一个平滑时钟消化，
样本按它自己的时间戳（系统时间线的 LastUpdatedTime）对齐；小偏差直接微调、
中等偏差用临时变速（最快 1.6 倍、最慢 0.55 倍）在约 1~2 秒内平滑吃掉，
显示进度**永不倒退**；只有偏差超过 2.5 秒（手动拖进度条、切歌）才直接跳。
无头实测：人为注入 +800ms 偏差，约 1.1 秒收敛到 100ms 内、稳态误差≈0、全程单调。

## 自动匹配策略（v0.3 改版）

不再是「按顺序谁先返回用谁」：先取缓存；无缓存时**并行向酷狗/QQ/网易云/酷我/LRCLIB
搜候选，给每个候选打分选最高的**（标题相同 +50、包含 +30；歌手命中 +30；
时长差 ≤2s +20 / ≤5s +10 / >10s −20；真逐字 +15；候选是 Live/翻唱/伴奏/铃声版
而原曲不是 −25；v0.6 加：标题差一两个字时按 Levenshtein 相似度给兜底分，
与目标完全不沾边的候选直接淘汰），最高分 ≥50 才采用；无人达标才回退到原来的
顺序逻辑（酷狗优先）。

**失败会重试**（v0.6）：取词失败先分类——网络型（超时/连不上）自动退避重试
（6 秒×次数、最多 3 次），耗尽后 60 秒还会自动再试一次；没收录/解析型立即收手。
不再像旧版那样失败一次就把这首歌永久放弃。

**实案：Beyond《長城》**（v0.6 修复）：真机曾报未找到歌词。复现数据：国内四源
按「长城」搜到的前排全是同名歌曲（马思唯/谭维维/徐小凤…），根本没有 Beyond 版；
只有 LRCLIB 有（100 分）。旧版 LRCLIB 只在回退链末端，整链走完要 9 秒且它当时
不可达就全盘落空、还永久放弃。v0.6 把 LRCLIB 候选纳入打分池后：**100 分直接
命中，总耗时约 3 秒**。顺带把各源候选上限从 10 提到 20，减少同名歌曲挤占。

实测（2026-11-11，本机网络）：

- 《晴天》周杰伦：新策略选中酷狗 KRC **115 分真逐字**（58 行）。修复过程中发现
  酷狗候选搜索默认给的是半截 KRC/DJ 版（时长只有 116s），已改为同时用歌曲哈希
  核验全曲候选参与打分——否则会被时长差误杀、只能拿到 QQ 的逐行版
- 《Nevada》Vicetone：酷狗 KRC 115 分真逐字（32 行）
- 《愛的供養》楊冪（繁体输入）：自动转简体搜索，选中 QQ 80 分（23 行）；
  酷狗此曲顺序逻辑拿到的是只有 4 行的残缺 KRC，新策略避开了它
- 新策略首次取词约 2.5~4 秒（并行打分），顺序逻辑约 1.3 秒；命中后走缓存秒开

歌词源顺序（回退链与手动选词）：酷狗 KRC → QQ 音乐 → 网易云 → 酷我 → LRCLIB →
lyrics.ovh → Musixmatch。酷狗是 KRC 逐字格式，能拿到毫秒级真逐字时间戳，扫光最准；
QQ/网易云是普通 LRC（带译文），逐字靠字符权重插值估算（安卓版同款算法）；
搜索关键词统一转简体后发送，每首歌会按最多 8 组关键词变体依次尝试（干净歌名+
主歌手优先，其后是去 feat./去括号内容/第一歌手等组合，v0.6 扩充）。

## 已知限制（如实）

- **自动更新的全链路真机未验证**：检查接口、版本比较、Release 解析已用真实
  GitHub 接口和假数据测过（假令牌正确得到 401 人话提示），Updater 的覆盖/重试/
  结果回写已在本机实测成功与失败两条路径；但「WMI 拉起 → 主程序退出 → 换版 →
  重启」整条链只能在 Windows 真机上验，**第一次实战就是 v0.4 → 下一版**。
  万一那次没成，看设置窗状态行与 `updater.log`，手动解压新版 zip 覆盖也能升级，
  不会把现有版本弄坏（Updater 覆盖失败时会先把旧版重新拉起来）。
- **Windows 真机 UI 手感未验证**：本插件在 Linux 上交叉编译，逐字引擎、取词、
  打分、广告判定、繁简转换、平滑时钟均有无头测试覆盖（v0.6 套件 50+ 项），
  匹配策略有多首歌的真实联网实测（含《長城》实案回归）；但 Fluent 窗口的 Mica
  质感、主题切换观感、按钮带动画、颜色盘点外部自动关、单行双居中等 UI 行为的
  手感需要你在真机上复验。WPF-UI 库本身在无头环境只做了编译级与资源合并验证。
- **切换主题时设置窗会关掉重开**：窗口的配色在构造时确定，切换预设靠「关掉重开」
  整体换装（位置记忆保证回到原位），代价是滚动位置重置、在设置里没保存完的
  输入（如正打一半的 hex）会丢——先让当前改动生效再切主题。
- 右击菜单的高亮细节仍是系统渲染；托盘右键菜单是系统菜单，保持原样。
- **实测环境是开发机（海外网络）**，2026-11-11 各源实测：
  - 酷狗 KRC：✅ 搜索+下载+解密全通；候选搜索混杂半截 KRC，见上文匹配策略一节
  - QQ 音乐：✅ 搜索与歌词接口通（base64 LRC 可正常解码）
  - 网易云：✅ cloudsearch 搜索与歌词接口通；候选里翻唱/网红版较多，靠打分区分
  - 酷我：✅ 搜索与歌词接口通；伴奏版候选会被打分压下去
  - LRCLIB：✅ 通，中英文都拿到同步歌词（排在国内源之后使用）
  - lyrics.ovh：✅ 通（纯文本，按时长均分时间轴，同步精度最低，只作兜底）
  - Musixmatch：⚠️ 免 key 桌面通道本机实测返回的是乱序假词（官方对未授权 token
    的反爬），大概率拿不到真词；如有 Musixmatch API Key 可在设置里填，走官方接口
- 逐字插值对英文连读、rap、句中长停顿的估算会有偏差，这是算法固有特性（安卓版同款）。
- KRC 歌词开头偶尔有一行制作名单（如「合声编写：…」），是酷狗源数据自带，安卓版同样如此。
