# SpotifyLyricsWin v0.2 使用说明

Windows 上播放 Spotify 时显示桌面悬浮歌词的小插件，外观与逐字算法按安卓版
SpotifyLyrics V2.4 复刻（见同目录《外观复刻规格.md》）。

v0.2 按真机试用反馈改了八处：设置实时生效、HSV 颜色盘、广告识别、手动选词、
应用图标与窗口最小化、锁定位置、单/双行模式与单行居中、代码入本地 Git 仓库。

## 怎么运行

1. 解压 `SpotifyLyricsWin-v0.2.zip` 到任意文件夹。
2. 双击 `SpotifyLyricsWin.exe`。
3. 打开 Spotify 桌面版放歌，悬浮歌词会自动跟上。

**运行前提**：需要 .NET 8 桌面运行时（框架依赖版）。如果双击没反应或弹缺运行时，
去微软官网装「.NET 8 Desktop Runtime (x64)」再试。程序不需要管理员权限、不改 Spotify 本体。

## 托盘操作

程序在系统托盘（绿色歌词图标）里：

- **双击图标**：打开设置
- **右键菜单**：显示/隐藏歌词、设置…、手动选词…、重新搜词、退出
- 图标悬停提示会显示当前歌词来源（如「歌词：酷狗 KRC｜晴天」）

## 悬浮窗操作

- **拖动**歌词：移动超过一点距离才算拖动，松手自动记住位置
- **轻点 / 鼠标悬停**歌词：右上角露出两个按钮（🔓/🔒 锁定、✕ 隐藏），3 秒后自动藏回去
- **锁定位置**：点 🔓 变 🔒 后整窗拖不动（按钮本身还能点）；设置里和右击菜单里也能切换，三处状态一致
- **右击歌词**：弹出菜单——打开设置、手动选词、重新搜词、锁定/解锁位置、隐藏歌词
- **双击**歌词：打开设置
- 暂停时歌词整块变淡（38%），恢复播放自动变回；关掉 Spotify 后显示「♪ 等待 Spotify 播放」

## 设置说明（v0.2 起：改动实时生效，没有保存按钮）

设置窗里任何改动都**立刻应用到悬浮窗**并自动存盘，窗口不会自己关，想关点「完成」或右上角 ✕。
窗口带任务栏图标和最小化按钮。

- **平滑逐字高亮**：卡拉OK 式渐变扫光；关掉则整行变色
- **显示译文**：歌词源带译文时（QQ/网易云）在当前行下方显示一行译文
- **锁定悬浮窗位置**：与悬浮窗上的 🔒 按钮等效
- **显示行数**：双行（当前行 + 下一行，默认）/ 单行（仅当前行；译文行仍按上面的开关）
- **歌词字号**：12~36，长句会自动逐级缩小（最低 11）不截断
- **高亮/文字颜色**：三种改法实时生效——填十六进制（#AARRGGBB）、点色块或「颜色盘…」
  打开 HSV 颜色盘（色板+色相条+12 预设+hex 四处同步）、点 12 个预设色
- **背景框透明度**：0 = 纯文字无框（默认推荐）；调高出现黑色圆角底框
- **歌词时间偏移**：歌词整体快/慢时用 ±0.1s 按钮微调，范围 ±30 秒
- **字体**：默认 Microsoft YaHei UI 粗体，可换系统里任意字体
- **Musixmatch API Key**：可选，见下方已知限制
- **恢复默认外观**：字号 18、绿高亮、白字、无背景框、逐字开（点击即实时恢复）

设置保存在 `%AppData%\SpotifyLyricsWin\settings.json`，歌词缓存（增强 LRC 文本）在
`%AppData%\SpotifyLyricsWin\cache\`，同一首歌第二次播放直接读缓存。

## 手动选词（v0.2 新增）

自动搜的歌词不对版时用：托盘菜单或右击歌词 →「手动选词…」。

1. 窗口打开时已预填当前曲目的歌名/歌手（可改，比如去掉歌名里的 Live/Remaster 后缀）
2. 点「搜索」：并行查酷狗 / QQ / 网易云 / 酷我 / LRCLIB，列表逐行显示
   来源、歌名、歌手、时长、逐字/逐行；某个源失败会在底部单独标明原因，不影响其他源
3. 选中一行（或双击）→「应用选中歌词」：立即换上，并记为当前曲目的歌词（覆盖缓存，
   下次播这首歌直接就是这版），行尾出现「✓ 已应用」

## 广告识别（v0.2 新增，启发式）

免费版 Spotify 放广告时，悬浮窗会变淡并显示「广告播放中 · 歌词马上回来」，
广告结束自动恢复歌词同步。

- 识别办法是看 SMTC 给的曲目信息特征：标题是 Advertisement，或歌手/专辑都为空
  且时长 ≤90 秒。判定刻意保守：信息不全但时长 >90 秒的纯音乐/播客片段不会被误判
- **局限**：这是启发式，个别把自己伪装成正常歌曲（有歌手、有专辑、时长像歌）的广告
  识别不了，会当成一首搜不到词的歌处理
- 每次命中都会记一行到 `%AppData%\SpotifyLyricsWin\log.txt`（时间/标题/歌手/命中规则），
  如果发现误判，把日志里那行发回来就能针对性调整

## 歌词源（顺序固定，命中即停）

酷狗 KRC → QQ 音乐 → 网易云 → 酷我 → LRCLIB → lyrics.ovh → Musixmatch

- 酷狗是 KRC 逐字格式，能拿到毫秒级真逐字时间戳，扫光最准
- QQ/网易云是普通 LRC（带译文），逐字靠字符权重插值估算（安卓版同款算法）
- 每首歌会按「歌名 歌手 / 歌名 / 去后缀歌名」等几种关键词依次尝试

## 已知限制（如实）

- **实测环境是开发机（海外网络）**，2026-11-11 实测结果：
  - 酷狗 KRC：✅ 搜索+下载+解密全通。周杰伦《晴天》、Vicetone《Nevada》、Coldplay《Yellow》
    三首均首发命中真逐字（58/32/44 行）。国内网络下应更快；本机首取《晴天》约 13 秒
    （多路尝试的超时累积），之后走缓存秒开
  - QQ 音乐：✅ 搜索与歌词接口通（base64 LRC 可正常解码）
  - 网易云：✅ cloudsearch 搜索与歌词接口通；搜索结果排序较杂，靠标题/歌手/时长过滤挑；
    手动选词时能看到全部候选，翻唱/伴奏版也在里面，认准原唱再应用
  - 酷我：✅ 搜索与歌词接口通；自动模式已把伴奏版降权，手动选词列表里仍可能出现
  - LRCLIB：✅ 通，中英文都拿到同步歌词
  - lyrics.ovh：✅ 通（纯文本，按时长均分时间轴，同步精度最低，只作兜底）
  - Musixmatch：⚠️ 免 key 桌面通道本机实测返回的是乱序假词（官方对未授权 token 的反爬），
    排在最后兜底大概率拿不到真词；如有 Musixmatch API Key 可在设置里填，走官方接口
- **手动选词候选实测**（2026-11-11，本机）：《晴天》酷狗 10 条、QQ 10 条、网易云 10 条、
  酷我 10 条候选均正常返回；LRCLIB 单独测 8 条正常，整组联测时出现过一次本机网络
  4 秒超时，被单独标成该源失败（其他源不受影响）——国内网络下这类超时应少得多
- **Windows 端的实际显示效果未在真机验证**：本插件是在 Linux 上交叉编译的，
  逻辑层（逐字引擎、取词、候选、广告判定）已用无头测试复跑过，但悬浮窗渲染、颜色盘
  手感、右击菜单、锁定、单双行居中这些 UI 行为需要你在自己电脑上复验。
  若悬浮窗不出字，先看托盘提示的状态文字，再把现象告诉 Muse。
- 逐字插值对英文连读、rap、句中长停顿的估算会有偏差，这是算法固有特性（安卓版同款）。
- KRC 歌词开头偶尔有一行制作名单（如「合声编写：…」），是酷狗源数据自带，安卓版同样如此。
